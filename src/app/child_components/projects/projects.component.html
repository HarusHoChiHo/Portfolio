RFPS back end application (Rust, Axum, SeaORM, PostgresSQL, Docker)

Visit the website View the source code on GitHub

This bakc-end application is developed with Axum and SeaORM for interactions between database and the application. It provides various API endpoints for accessing and modifying data. All of the data are stored in Postgres database, which is a popular option for data storage. To ensure a easy deployment to different cloud platform, I decided to build this application as a docker image. That allows the application to be deployed to different platforms without dramatic changes. It works even some platforms do not have native support for Rust. For application release, Railway is chosen to host this application. It is a cloud platform provides software as a service and supports automated deployment, where each time a push to this repo happens the platform will automatically build and deploy the latest version of the application. The whole deployment process will be getting Dockerfile ready, pushing changes to GitHub, and monitoring the deployment process through Railway's dashboard. Upon the deployment is done, I will do some testings through the Swagger UI to ensure the application works well. Overall, this web application is developed in Rust, providing endpoints for users to retrieve and edit data in database by sending requests to the service and receiving responses from the service via HTTP endpoints. All data in requests and responses are in JSON format, which is a standard data format in API development.

Restaurant Food Planning System (Next.js, .Net Core, EntityFramework Core, PostgresSQL)

Visit the website View the source code on GitHub

In my third semester at Centennial College, I collaborated with another teammate to develop this website.

The initial idea of this system was to streamline a restaurant's ingredients management. By setting the ingredient consumption for each dish, each time the staff make orders for customers, the system would reduce the amount of ingredients and reflect the changes on the admin portal. Restaurant managers are able to closely monitor the ingredient consumption and its stocks. That allows the managers make a clear plan on ingredients purchasing or promotion to accelerate some ingredients' consumption. Overall, it could simplify the ingredients management and prevent potential loss due to procuring surplus ingredients.

In conclusion, the website aims to boost client's product promotion by allowing client to publish articles. The whole system includes features: standard user authentication, APIs, multi-function text editor.
